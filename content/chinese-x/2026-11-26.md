## Obsidian @obsdmd

**宣布为各家 Agent 提供官方 connectors**：官方写这样可以把共享知识库交给 Agent 用，同时数据仍由用户完全所有；知识可以按笔记、图表、canvas、表格、看板来组织，并保存在本地设备上的开放格式文件里，可离线访问。他们重申 Obsidian 没有内置 AI，不要求账号，没有分析，也不能访问用户数据，默认是完全不用 AI，也可以换 Agent 或让多个 Agent 协作。若要把仓库交给 Agent，他们让去各家的 marketplace 或插件目录看，并写已可用于 Claude、ChatGPT、Grok Bot、Hermes 等，这条正文里说「说明在下面」，但帖子实体链接只有配图 [原帖](https://x.com/obsdmd/status/2125700941156651151)

## yetone @yetone

**认为 Antigravity 不是接了 ACP 就不会封**：有人以为 T3 这类多 Agent 编排走 ACP，所以用 Gemini 订阅不容易封号。yetone 回复说，必须还是 thin-client editor，否则照样会封 [原帖](https://x.com/yetone/status/2125806965096095780)

**解释在 Magpie 里统一管理 MCP 的好处**：一是像 Notion、Linear 这种要登录授权的 MCP，只需在 Magpie 登录一次，换 Agent 不用重新登录；二是可以统一做版本更新和安装卸载。有人觉得 Antigravity 里 Notion MCP 一次塞进 77 个工具、大约占 8k token，他建议改用 Magpie 的 MCP 路由 [好处](https://x.com/yetone/status/2125882529932816573) [路由](https://x.com/yetone/status/2125874416995450998)

**谈人类相对 AI 的一点优势**：他写可能在于阅读沉默，对人类交流来说，TTFT 越长反而是越好的 [原帖](https://x.com/yetone/status/2125626786709168459)

会不会封号、以及 Magpie 能否省掉重复授权，都是他根据自己使用给出的判断

**Xcode 多 Agent 并行编译**：Baye @waylybaye 发了一篇 X 文章，标题是「使用 Xcode 多 Agent 并行开发时，最快的编译方式」。他的做法是每个 worktree 单独一份 Derived Data，再开启全局共享的 CAS 编译缓存，并配好 Prefix Mapping，让不同目录也能命中缓存。他写每个 worktree 冷编译只需几十秒，文章是 [x.com/i/article/2125875151351033856](https://x.com/i/article/2125875151351033856) [原帖](https://x.com/waylybaye/status/2125881503905460570)

**Kinopio 连接线位置可拖了**：Kinopio @KinopioClub 写应大家要求，拖动以改变 connector position 已进入 beta [原帖](https://x.com/KinopioClub/status/2125627100862222471)
